# ADR-0008: 화면에 보이는 문자열은 core의 뷰가 만든다

- 상태: 채택 (2026-08-30, 아키텍처 리뷰 후)

## 배경

첫 구현에서 오전/오후·요일·항목 라벨 계산이 네 곳(core `slots`, core `render`, 프론트 `format.ts`, 프론트 라벨 테이블)에 있었고, 요일 테이블은 인덱스 기준까지 달랐다. ADR-0001의 "프론트엔드는 계산을 하지 않는다"와 어긋난다.

## 결정

- core에 **뷰** 모듈(`view.rs`)을 둔다. `SheetView`(작성 시각 라벨 + 항목별 라벨), `SheetSummary.created_label`, `Catalog`(품목·구역 키와 라벨, 표시 순서)가 화면에 필요한 모든 문자열을 만든다.
- 조사표를 돌려주는 커맨드(`create_sheet`, `get_sheet`, `save_sheet`)는 `SheetView`를 반환한다. 뷰 JSON은 저장 형식의 상위 집합이라 `save_sheet` 인자로 그대로 되돌려 보낼 수 있다(`Sheet`는 모르는 필드를 무시한다).
- 이미 지난 슬롯의 항목을 편집할 때 필요한 라벨도 core가 만든다: `slot_options(product, include)`가 그 슬롯을 `past: true` 날짜로 끼워 넣는다.
- 프론트엔드에는 날짜·요일·시각 포맷 코드와 품목·구역 라벨 테이블을 두지 않는다. `format.ts`는 삭제됐다.

## 이유

- 국소성: PNG와 화면이 같은 함수의 출력을 쓰므로 어긋날 수 없다. 표기를 바꾸면 한 곳만 고친다.
- 레버리지: 라벨 규칙은 이미 core에 테스트가 있다. 프론트에 테스트 러너를 추가하지 않고도 검증된다.

## 결과

- 화면 시작 시 `catalog` 커맨드를 한 번 호출한다.
- 뷰와 저장 형식이 분리되어, 저장 파일에 키가 빠져 있어도(`get_sheet`는 정규화하지 않는다) 뷰가 키를 채워 화면이 죽지 않는다.
