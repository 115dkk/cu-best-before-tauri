# ADR-0007: Android 뒤로 가기는 WebView 히스토리로 처리한다

- 상태: 채택 (2026-08-30)

## 배경

Tauri 2 Android의 `AppPlugin`은 뒤로 가기 제스처/버튼을 받으면 `webView.canGoBack()`이면 `goBack()`, 아니면 액티비티를 종료한다. SPA인 이 앱은 URL이 바뀌지 않으므로 아무것도 하지 않으면 첫 뒤로 가기에 앱이 닫힌다.

## 결정

- 화면 전이와 슬롯 선택 시트 열림을 `history.pushState`로 한 칸씩 쌓고, `popstate`에서 상태를 복원한다(`src/lib/nav.svelte.ts`).
- 히스토리 항목이 화면 상태의 **유일한 진실**이다: `{ screen, picker }`. 시트가 열렸는지와 무엇을 편집하는지(`PickerTarget`)를 함께 담아, 화면 쪽에 별도 상태를 두지 않는다.
- 불변식: 시트 항목은 항상 편집 화면 항목 바로 위 한 칸이다. `goHome()`은 시트가 열려 있으면 `history.go(-2)`, 아니면 `history.back()`.

## 이유

- Kotlin 코드나 플러그인 없이 플랫폼 관례(뒤로 = 한 단계)를 그대로 얻는다.
- 자동 저장(ADR-0004) 덕에 뒤로 가기로 화면을 떠나도 잃는 것이 없다.

## 결과

- 데스크톱 개발 창에서는 브라우저 뒤로 가기 단축키가 같은 동작을 한다.
- 히스토리 깊이는 최대 2(홈 → 편집 → 시트)이므로 다른 화면을 추가하면 `goHome`의 `-2` 가정을 갱신해야 한다.
