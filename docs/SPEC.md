# 소비기한 조사표 앱 — 요구사항 명세 (goal)

개인용 Android 앱. 편의점 상품 다섯 품목의 소비기한을 손으로 적던 일을 폰에서 빠르게 작성하고, PNG로 저장해 공유·보관한다. 용어는 [CONTEXT.md](../CONTEXT.md)를 따른다.

## 1. 손글씨 원본 레이아웃 (참고 사진 해석)

A4 용지를 가로선 하나로 위(매장)/아래(워크인) 두 구역으로 나누고, 각 구역 오른쪽에 품목 이름을 세로로 나열한 뒤 품목마다 "날짜.시각 수량" 줄을 적는다.

```
┌──────────────┬───────────────────────────────┐
│ 매장         │ 삼각   30.14시 12개            │
│              │        31.02시  6개            │
│              │ 김밥   31.02시  1개            │
│              │ 도시락 30.14시  1개            │
│              │        31.02시  4개            │
│              │ 샌드   30.10시  4개            │
│              │ 버거   30.10시  2개  31.10시 1개│
├──────────────┼───────────────────────────────┤
│ 워크인       │            ╲   ╱               │
│              │              ╳    (비어 있음)  │
│              │            ╱   ╲               │
└──────────────┴───────────────────────────────┘
```

- 한 품목에 여러 슬롯이 있으면 여러 줄로 적는다.
- 항목이 없는 품목은 적지 않는다(생략).
- 구역 전체가 비면 칸 전체를 X로 채운다(엑셀의 대각선 테두리와 같은 표현).
- 시각은 24시간제 두 자리(02시, 14시, 10시, 22시).

앱은 이 종이를 그대로 흉내 내는 것이 아니라 **스마트폰 화면에 맞는 레이아웃**으로 입력을 받고, 저장 이미지에서 위 표 구조를 깔끔하게 재현한다.

## 2. 도메인 규칙

1. 품목은 다섯이며 순서 고정: 삼각김밥, 김밥, 도시락, 샌드위치, 햄버거.
2. 기한 시각대: 삼각김밥·김밥·도시락 = 02시·14시 / 샌드위치·햄버거 = 10시·22시.
3. 후보 슬롯은 `now`보다 **엄격히 미래**인 슬롯부터 시작한다.
   - 8/1 01:00 실행 → 도시락 첫 후보 8/1 02:00.
   - 8/1 03:00 실행 → 도시락 첫 후보 8/1 14:00.
   - 8/1 02:00 정각 → 02:00은 제외, 첫 후보 14:00.
4. 후보 범위는 오늘부터 14일 뒤까지(`horizon_days = 14`).
5. 항목 수량은 1 이상의 정수. 같은 구역·품목·슬롯의 항목은 하나로 합친다(수량 합산).
6. 구역은 매장, 워크인 둘.

## 3. 화면

- **홈**: 저장된 조사표 목록(최신순, 작성 시각·항목 수), "새 조사표" 버튼. 항목을 누르면 편집 화면.
- **편집**: 상단에 매장/워크인 구역 탭. 아래에 다섯 품목 카드가 순서대로 항상 표시된다(항목이 없어도 표시). 카드에는 항목 목록(슬롯 라벨 + 수량 + 삭제)과 "추가" 버튼. 기한이 이미 지난 항목은 라벨 옆에 작은 '지남' 표시가 붙는다(판정은 core의 `past`).
- **슬롯 선택 시트**: 참고한 iOS/One UI 시간 휠 인터페이스. 휠 세 개 — **날짜 휠**(오늘부터 14일, "8/30 (일)" 형식) + **시각 휠**(그 품목의 두 기한 시각대, "오전 2시 / 오후 2시") + **수량 휠**(1~99개, 드롭다운 대용). 첫 날짜처럼 과거 슬롯이 섞인 날은 미래 슬롯만 보인다. 확인 시 항목 추가.
- **내보내기**: 편집 화면 상단 버튼. 성공 시 저장 경로를 토스트로 표시.
- 편집 내용은 바뀔 때마다 즉시 저장된다(뒤로 가기·앱 종료·새 조사표 시작 시 잃지 않는다).
- 다크 테마 기본, 세로 모드, 안전 영역(노치/제스처 바) 고려.

## 4. 저장 이미지 (PNG)

- Rust에서 렌더링. 폰트는 Pretendard(OFL) Regular/Bold 번들.
- 너비 1200px 고정, 높이는 내용에 따라 결정. 흰 배경, 검정 글자·선.
- 헤더: 제목 "소비기한 조사표", 작성 시각 "2026.08.30 (일) 오전 8:02".
- 표: 열 = [구역 | 품목 | 항목]. 구역 셀은 그 구역의 품목 행들을 세로로 합친다.
- 항목 열은 한 줄에 한 항목: `8/30 14시 12개` (월/일 + 24h 두 자리 + 수량).
- 항목이 없는 품목 행은 생략. 구역 전체가 비면 품목+항목 칸을 합친 한 행에 두 대각선 X로 채운다.
- 파일명 `소비기한_YYYY-MM-DD_HHMM.png`(작성 시각 기준), 위치 `Pictures/소비기한/` (기기 공용 사진 폴더 하위, 갤러리에 보임). 경로 지정 기능 없음.
- 같은 조사표를 다시 내보내면 덮어쓰지 않고 `소비기한_YYYY-MM-DD_HHMM (2).png`, `(3)` … 로 **새 파일**을 만들고 이전 파일은 지운다. 덮어쓰면 갤러리가 새 사진으로 보지 않아 맨 앞에 올라오지 않기 때문이다. 조사표 하나에 파일은 항상 하나만 남는다.

## 5. 저장·보존

- 조사표는 앱 데이터 폴더의 `sheets/<id>.json`으로 저장. `id = created_at`을 `YYYYMMDD-HHMMSS`로 포맷.
- 앱 시작 시 `updated_at`이 30일보다 오래된 조사표는 삭제.

## 6. 플랫폼·품질

- 대상 기기: Galaxy S26 Ultra / Android 16. `minSdk = 30`(Android 11 스코프드 스토리지 직접 경로 쓰기가 필요한 최저선). 하위호환 우선순위는 극도로 낮다.
- 스택: Tauri 2 + Svelte 5 + TypeScript(화면) / Rust(로직 전부). `unsafe` 금지(필요 시에만 Miri 추가).
- CI: push·PR에 rustfmt, clippy(`-D warnings`), 테스트, TypeScript 타입 검사. PR에는 `cargo check` 추가. main push에 Android APK 빌드·서명·GitHub Release.
